# Local Question Ingestion (no n8n)

Replicates the **n8n ingestion sink** on your machine. Parsing stays identical to the
current pipeline; only the "embed + hash + write to Supabase" step (which n8n used to
do) now runs locally. Ingested rows are consumed **unchanged** by `phase_1`, `phase_2`,
`phase_3`.

```
PDF(s) ──▶ ../ingest/ingest_pdf.ingest()        ──▶  sink.py
           text layer  OR  Gemini Vision OCR          embed (gemini-embedding-001, 768d)
           (handles text AND image/handwritten        + simHash (phase_1 algorithm)
            PDFs — same code the live ingest uses)     + pHash (figures)
                                                       + Supabase REST upserts
```

| Parser output | Table written | Workflow that reads it |
|---|---|---|
| `question` | `public.questions` (`question_embedding`, `solution_md`, …) | `questions_text_search` (phase_1) — vector match |
| `chunk` | `public.knowledge_chunks` (`embedding`, `chunk_text`) | `knowledge_chunks_search` (phase_1) — RAG context |
| `figure` (`--with-figures`) | `public.question_cache` (`phash_col`, `simhash_binary`) | `simhash_lookup` / `phash_lookup` (phase_1/2) |

## Files (this folder)
- `sink.py` — embeddings, simHash, pHash, Supabase REST writers.
- `run.py` — driver: parse a PDF / folder tree, then push to Supabase.
- `ensure_columns.sql` — idempotent, run once before first ingest (adds missing columns only).
- `requirements.txt`, `.env.example`.

It reuses the proven parser at `../ingest/ingest_pdf.py` and `../ingest/ingest_multi.py`
(no changes to those files).

## Verify it's queryable by the workflow
After ingest, embed any question text and call `questions_text_search` (the exact RPC
phase_1 uses). A freshly-ingested question should return a small `distance` and its
`solution_md`.

## Notes
- **Vector column** on `questions` is `question_embedding` (verified) and on
  `knowledge_chunks` is `embedding`. Both 768-d, same `gemini-embedding-001` model as
  phase_1, so query and stored vectors share one cosine space.
- **Text vs image PDFs**: handled per *page* — pages with no text layer are OCR'd via
  Gemini when `--ocr-backend gemini` is set; text pages use the fast regex path. Mixed
  PDFs work automatically.
- **Idempotent**: upserts on `(source_doc, q_no)` for questions and
  `(source_doc, page_number, chunk_index)` for chunks — safe to re-run.
- **Figures** (`--with-figures`) use a standard DCT pHash. If your live `question_cache`
  pHash was generated by a different algorithm, cross-pipeline figure hits may not match;
  the primary vector path (questions / knowledge_chunks) is unaffected.
